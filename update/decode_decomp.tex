\subsection{Full-Inference DeepSeek: One Chip, Prefill and Decode}
\label{sec:decode_decomp}\label{sec:batch_sensitivity}
We examine a DeepSeek-V3 checkpoint to 32 independent requests, each
with 4,096 prompt and 512 output tokens. All 61 layers execute, prefill produces
the first output, followed by 511 decode forwards. Actual expert IDs and aligned
routing weights define the task. The recovered execution covers all
$61{,}985{,}244$ original invocations in $41{,}987{,}272$ groups. Original FP8
weights are dequantized to BF16 on demand and conversion is charged separately.
The capture uses expanded attention and the full KV history, with no assumed
quality gain from changing precision or dropping tokens.

The single custom chip has 384 $16\times16$ MAC arrays, 4,096 vector lanes,
89.875 MiB SRAM, 64 GiB DRAM and 2 TiB backing storage. Its declared rates are
2,608 GB/s DRAM, 1,024 GB/s external and 16,384 GB/s local service at a 1 ns
analytical clock; existing area/power proxies give $312.21$ mm$^2$ and $284.95$ W.
The full-task TPU-v3 extension uses the original compute/DRAM resources with
32 GB/s external, 8,192 GB/s local, and 2,048 primitive vector cycles/ns.
These interface assumptions are part of the comparison, not measurements of
a complete TPU system.

Decode accounts for $80.39\%$ of the predicted time saved, prefill $19.45\%$,

on this replayed execution.

\subsection{What Each Feature Contribute}
\label{sec:native_features}


\paragraph{Batching and fusion.}
Compatible GEMMs share matrix execution while retaining each request's identity.
The no-batch control retains weight residency and chooses each member's best
tile, so the gain isolates grouped execution rather than repeated parameter
loads. Small decode matrices benefit most. SwiGLU fusion keeps primitive
intermediates in installed vector scratch, removing spills while preserving
arithmetic, BF16 rounding, and local/vector service. It helps both phases but
saves more time in prefill. This is storage fusion within SwiGLU, not a
multi-GEMM gate/up/down pipeline.

\paragraph{KV persistence and time-indexed placement.}
Every arm already uses cached decoding with the full history. Five retained
layers require 163,840 paid host-to-DRAM copies, checked for source validity,
reservation, readiness, and terminal backing. Reusing prefill's temporary region
allows five layers to fit after prefill; a fixed partition fits two. The
$14.901$-second placement gain is therefore \emph{included} in the $24.835$-second
KV gain and not added to it. Only five of 61 expanded layer caches fit,
and the wide custom interface limits the marginal value of eliminating reads.
Backing and transfer completion are correctness costs, not features that can
be removed for a valid speedup.
