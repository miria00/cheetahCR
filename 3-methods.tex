\section{CHEETAH Formulation for HW/SW Co-Design}
\label{sec:methods}
CHEETAH minimizes predicted workload inference latency under a declared hardware
budget. Its inputs are independent logical invocations, a finite implementation
library, and a numerical contract. Each whole-program branch specifies compatible
hardware and execution semantics; hardware is shared across all invocations within
that branch. The same master template admits the retained joint tiling--placement
model and causal execution branches. The strengthened physical branches add
direct installed-resource ceilings. The earlier DeepSeek certificate applies to
its frozen family of 21 native branches, not automatically to these new rows.

\subsection{Pruning, Variables, and the Encoded Features}
\label{sec:v1}\label{sec:master_lp}\label{sec:v3}
\paragraph{Pareto pruning pre-pass.}
For each operation, we discard infeasible tiles and configurations dominated
in every relevant cost, traffic, workspace, and interface dimension.
Dominance is tested within the same implementation contract and hardware class:
a lower isolated latency alone is insufficient. Timeloop or a native analytical
recipe supplies the retained coefficients once; the solver then selects among
them without invoking the mapper at each iteration. Reuse across hardware
settings requires that the same dominance relation remains valid.

Let $i\in\mathcal N$ index logical nodes (invocations and required conversions), $j\in\mathcal J$ storage
objects, $e\in\mathcal E_b=\{0,\ldots,E_b-1\}$ events in branch $b$, and $\tau$ memory tiers. An implementation
$k$ covers members $S_k$ and specifies inputs, outputs, workspace $W_{k\tau}$,
and resource demands. States also have the exit index $E_b$.
$\mathcal K_b$ is the complete finite implementation set of branch $b$, generated
on demand without tying same-shaped invocations. Table~\ref{tab:var_digest}
defines its coordinates.

Partition the declared family as $\mathcal B=\mathcal B_C\mathbin{\dot\cup}\mathcal B_P$:
causal branches and, when included, retained joint tiling--placement branches.
The objective charges causal event durations and retained operation latencies
plus rematerialization. $\kappa_b$ converts ns to ms;
$\alpha_b$ converts the retained block's cost units to ms. Each $x_b$ contains
the complete branch coordinates, already scaled by $\lambda_b$; the objective
does not multiply them by $\lambda_b$ again. Right-hand sides and finite bounds
scale likewise. In the causal rows below we suppress branch indices
and write $E=E_b$. $\mathcal R_k$ lists required object/tier pairs,
$\mathcal D_k$ completed controls, and $\mathsf D^r_e$ is linear resource demand.
$\mathsf{Cap}_{b,\tau e}$ includes live objects, incoming copies, active outputs,
workspace and dedicated reservations. $B_b,J_b$ contain the remaining state,
backing and implementation rows, expanded in Appendix~\ref{app:master_rows}.
For $b\in\mathcal B_{\rm phys}\subseteq\mathcal B_C$, the installed chip
$\bar h_b$ fixes resource rates $\bar R_{br}$, and $\mathsf D^{r,\rm phys}_{be}$
is the total issued work or traffic sharing resource $r$ at event $e$.
$\mathsf A_b^\lambda=a_{b0}\lambda_b+a_b^Th_b$ and
$\mathsf P_b^\lambda=p_{b0}\lambda_b+p_b^Th_b$ denote area and peak power.

\subsection{Features and Their Mathematical Encoding}
\label{sec:v3_levers}\label{sec:v0}
\paragraph{Joint tiling and fusion.}
For an isolated operation, the cover row reduces to $\sum_c y_{i,c}=1$.
A tile's traffic savings depend on residency. In the retained schedule block,
$w_{ick}$ represents $y_{ic}p_{\mathrm{assoc}(i,k),o(i)}$ through
\begin{equation}
0\le w_{ick},\quad w_{ick}\le y_{ic},\quad w_{ick}\le p,\quad
w_{ick}\ge y_{ic}+p-1.
\label{eq:mccormick}
\end{equation}
These McCormick inequalities give the convex hull of one bounded bilinear graph
and fix the product when either binary-domain factor is integral~\citep{mccormick1976computability}; they do not
make every fractional solution executable. Tile-dependent footprints use the
same construction. The displayed unit-bound rows are for a branch at weight
one; homogenization replaces $1$ by $\lambda_b$. Native fused atoms carry their complete input,
output, workspace and service recipe, so fusion cannot silently remove work.

\paragraph{Shared hardware and resource epigraphs.}
Compute, vector lanes, SRAM, and delivered memory service are shared decisions
under linear area/power proxies $F_bh_b\le g_b$. Finite implementation or
technology menus use disaggregated copies with linking equalities and scaled
bounds. Resource epigraphs charge the maximum of concurrent service demands,
while demands on the same port add. Native rows aggregate work and transfer
demands per event before applying the service envelopes. Arbitrary executable
overlap is not inferred from fractional sharing; native replay uses its
declared inter-kernel ordering and internal panel pipelines.

\paragraph{Hard rooflines and physical budgets.}
The strengthened fixed-chip branches enforce resource ceilings \emph{inside the LP}:
$\sum_k F_k^{\rm issued}w_{ke}\le\bar C_b d_e$ for matrix work, and
$\mathsf D^{r,\rm phys}_{be}\le\bar R_{br}d_e$ for shared HBM, host, vector,
DMA-staging and SRAM-bank-port service. Padded issued work bounds useful work;
simultaneous kernels and copies share the same supply. Summing over events
therefore gives MFU and accounted MBU at most one. Affine installed-component
costs enforce area $\le600\,\mathrm{mm}^2$, peak power $\le300\,\mathrm W$ and
chip-average density $\le2\,\mathrm{W/mm}^2$, without discounting peak power by MFU.
The same identified template supplies combined host/HBM pin, controller,
whole-bank capacity/count/aspect, logic-depth and NoC-size constraints in
$F_bh_b\le g_b\lambda_b$. Fixed rates keep these ceilings linear; a
variable-rate McCormick envelope alone cannot enforce the exact physical
product. These are hard limits of the declared analytical model, with the same
predicates used in recovery. Aggregate bank and NoC proxies do not prove
conflict-free arbitrary placement. Appendix~\ref{app:physical_rooflines} gives
the rows and distinguishes their current implementation from the frozen certificate.

\paragraph{Reciprocal and product envelopes.}
For a rate $r\in[\ell,h]$, $\mathcal R$ bounds $u\approx1/r$ by tangents
$u\ge2/a-r/a^2$ and the global secant $u\le(\ell+h-r)/(\ell h)$.
$\mathcal M$ bounds $Z\approx Qu$ by the four McCormick inequalities on
$[0,\bar Q]\times[1/h,1/\ell]$. All coefficients are constants, so the program
is linear. Outward coefficient rounding preserves graph containment.
These are relaxations of physical service; replay reinstates the exact rates
and products. Selecting a discrete bandwidth fixes that rate, but continuous-rate
envelopes remain relaxations even when implementation selectors are integral.

\paragraph{Time-indexed placement and KV across steps.}
Residency $p_{j\tau e}$ changes with events rather than being fixed for the whole
run. KV production creates immutable append objects; each decode attention
operation depends on its required prefix. The state rows preserve earlier
entries while the prefix grows. Capacity accounts for resident data, incoming
copies, and active workspace simultaneously. Long skip connections and
multi-fanout tensors use the same object identities and consumer readiness.

\paragraph{Spill, restoration, and rematerialization.}
Copies retain a valid source, reserve their destination, consume service, and
become readable only after completion. Boundary rows require the declared
terminal backing. A permitted repeat executes the original producer again and
pays its work, input and workspace demands; it restores storage without
advancing primary logical completion twice. Keeping full KV history in a
slower tier is therefore different from deleting history. The native results
credit paid KV restoration and retention; no native recomputation gain or lossy
KV budget is claimed.

\paragraph{Batching and causal scheduling.}
A batch column covers several compatible invocations and loads shared parameters
once where its recipe permits. Cover constraints retain every member;
start/finish and readiness rows prevent using future tokens or expert selections
before their router dependencies complete. Event placement can vary within the
finite library. The current native execution uses a recovered serial schedule;
a larger scheduling domain does not imply that its optimum has been found.

\paragraph{Implementation menus and recovery.}
Parameter staging has explicit receive, occupancy and drain states. Full-K
panels and FP8-to-BF16 receiver implementations pay buffer, port and conversion
costs. Selected-reader backing keeps the raw or converted representation needed
by each consumer; it cannot discard both. These rows connect hardware provisioning
to software reuse.
Precision, sparsity, array aspect, memory technology, and validated overlap
policies enter as implementation choices with their own numerical and resource
contracts. Accuracy-changing cache eviction or approximate reuse needs separate
quality evidence; it is pinned off in the full-input native result. Larger
cross-GEMM fusion and unrestricted overlap have no credited gain there.
Recovery pins hardware and mappings, schedules transfers, and replays the
original obligations. The resulting chip and schedule have a predicted latency
under the analytical model. Section~\ref{sec:ocs} distinguishes hardware
branch-and-bound, continuous LP certification, and integral recovery.

\subsection{LLM Architect Diagnostic Outer Search}
\label{sec:llm_outer}
The LLM architect reads a ledger of resource prices, slacks, invalid trials,
and replay outcomes, then proposes candidate implementations or search
neighborhoods. Deterministic validation checks each proposal before evaluation.
The original campaign uses Vizier~\citep{google_vizier} to search hardware
neighborhoods; the native master also represents hardware choices directly.
Dual prices guide search,
but an LLM proposal is not a complete pricing oracle: a full-domain optimality
claim requires checking all omitted alternatives. The original controller and
prompts are documented in Appendix~\ref{app:llm_loop}.
